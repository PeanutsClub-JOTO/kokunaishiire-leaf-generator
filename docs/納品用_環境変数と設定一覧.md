# 企画業務自動化システム 環境変数・定数・機密整理

作成日: 2026-07-23（更新: 2026-07-24）

## 1. 目的

この資料は、本番運用に必要な環境変数、定数化された計算値、Google Drive関連情報、機密情報の扱いを整理するためのものです。


- APIキーや秘密鍵はこのドキュメントに直接書かないでください。
- 先方共有用には「どこに設定するか」「誰が管理するか」までを記載します。
- 実際の値はVercel、Supabase、Google Cloud、社内パスワード管理などで管理します。

## 2. 本番で必要な環境変数

### 認証

| 変数名 | 用途 | 機密 | 備考 |
|---|---|---:|---|
| `APP_ACCESS_PASSWORD` | 本番画面のログインパスワード | 機密 | 城東さんから共有 |

パスワードについて:

- パスワードは情シス課長の城東さんに決めていただいたものを使用します。
- クライアントへの共有も城東さん経由が望ましいです。
- GitHub、README、チャット、資料内に実値は書かないでください。

### Supabase

| 変数名 | 用途 | 機密 | 備考 |
|---|---|---:|---|
| `NEXT_PUBLIC_SUPABASE_URL` | SupabaseプロジェクトURL | 公開可 | 画面側でも使うため公開前提 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | ブラウザ用公開キー | 公開可 | RLS前提の公開キー |
| `SUPABASE_SERVICE_ROLE_KEY` | サーバー処理用管理キー | 機密 | 絶対に公開しない |

注意:

- `SUPABASE_SERVICE_ROLE_KEY` はDB更新、Storage操作、ワーカー処理に使います。
- GitHubやクライアント向け資料に実値を載せてはいけません。

### Gemini

| 変数名 | 用途 | 機密 | 備考 |
|---|---|---:|---|
| `GEMINI_API_KEY` | OCR、文章生成、画像生成 | 機密 | Google AI Studio / Google Cloud側で管理 |
| `LLM_MODEL` | OCR、文章生成用モデル | 公開可 | 既定: `gemini-3.1-flash-lite` |
| `IMAGE_GEN_MODEL` | AI背景画像生成モデル | 公開可 | 既定: `gemini-3.1-flash-lite-image` |

注意:

- `GEMINI_API_KEY` がないとOCRやAI背景生成が失敗します。
- `IMAGE_GEN_MODEL` は背景生成だけに使います。
- 商品画像そのものはAIで生成しません。

### Google Drive / Service Account

| 変数名 | 用途 | 機密 | 備考 |
|---|---|---:|---|
| `GOOGLE_SERVICE_ACCOUNT_EMAIL` | Drive API用サービスアカウント | 原則公開可 | 共有先として使う |
| `GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY` | サービスアカウント秘密鍵 | 機密 | 絶対に公開しない |
| `GOOGLE_DRIVE_FINAL_LEAF_FOLDER_ID` | 確定リーフ転送先フォルダID | 社内管理 | URL自体は共有先に応じて判断 |

Drive側の事前設定:

1. 確定リーフを保存するGoogle Driveフォルダを作成します。
2. `GOOGLE_SERVICE_ACCOUNT_EMAIL` のメールアドレスを、対象フォルダに編集者として共有します。
3. フォルダURLからフォルダIDを取得します。
4. そのフォルダIDを `GOOGLE_DRIVE_FINAL_LEAF_FOLDER_ID` に設定します。

フォルダIDの見方:

```text
https://drive.google.com/drive/folders/ここがフォルダID
```

実際に使うDriveフォルダ:

```text
フォルダ名: リーフ画像確定
フォルダID: 1pGINY-Avt5bjrqNn_BD3BFPILC0E4AEz
```

### ワーカー / 画像レンダリング

| 変数名 | 用途 | 機密 | 備考 |
|---|---|---:|---|
| `WORKER_BASE_URL` | 画像/PDF生成ワーカー（Railway）のURL | 社内管理 | Vercel側に設定。未設定だとVercel上で直接Puppeteerを起動しようとしてエラーになります |
| `RENDERER_PORT` | レンダラーの待受ポート（Railway側） | 公開可 | 既定: `3001` |
| `NOTO_FONT_URL` | 日本語フォントURL | 公開可 | 任意 |
| `PUPPETEER_LAUNCH_TIMEOUT_MS` | Puppeteer起動待ち時間（Railway側） | 公開可 | 既定: `60000` |

`WORKER_BASE_URL` はVercel側に設定する変数で、値としてRailway上のワーカーの公開URLを指定します。Railway側の環境変数一覧は「5. Railway」の章を参照してください。

### Cron設定

Cronは `vercel.json` にコード上設定済みです。

設定内容:

| Path | Schedule | 日本時間の目安 | 用途 |
|---|---|---|---|
| `/api/cron/cleanup` | `0 3 * * *` | 毎日12:00頃 | 期限切れ見積書の削除 |
| `/api/cron/ocr-tune` | `0 4 * * *` | 毎日13:00頃 | OCR改善用の拡張処理 |

注意:

- Vercel側でCron機能が有効なデプロイで動作します。
- 現時点の認証用環境変数は `APP_ACCESS_PASSWORD` のみです。

## 3. 定数化された計算値

計算設定は `app_settings` テーブルに保存されます。

| キー | 現在値 | 用途 |
|---|---:|---|
| `profit_coef` | `0.75` | 卸売価格計算の除数 |
| `sales_add` | `3000` | 最後に加算する営業上乗せ額 |
| `unit_price_cap` | `1000` | 掲載単価の上限 |
| `cost_cap` | `33000` | 仕入原価合計の上限 |
| `half_base` | `16500` | ハーフ可否判定基準 |
| `shelf_min_days` | `90` | 賞味期限の通過基準 |

卸売価格の計算:

```text
卸売価格 = 仕入原価合計 ÷ 0.75 + 3,000円
```

注意:

- DBキー名 `profit_coef` は既存互換のため残しています。
- 現在の意味は「掛率」ではなく「除数」です。

## 5. 本番環境ごとの設定場所

### Vercel

Vercelを本番入口にする場合、以下をVercelのProduction環境変数に設定します。

必須:

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY`
- `APP_ACCESS_PASSWORD`
- `GEMINI_API_KEY`
- `LLM_MODEL`
- `IMAGE_GEN_MODEL`
- `GOOGLE_SERVICE_ACCOUNT_EMAIL`
- `GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY`
- `GOOGLE_DRIVE_FINAL_LEAF_FOLDER_ID`

任意:

- `WORKER_BASE_URL`
- `NOTO_FONT_URL`
- `PUPPETEER_LAUNCH_TIMEOUT_MS`

注意:

- 環境変数を変更したらRedeployが必要です。
- VercelのURLを使う場合、Railway側だけに環境変数を入れても反映されません。

### Railway

**Railwayは現在、ワーカー本体として常時稼働しています。** Vercelとは別に、Railway側の対象サービスにも以下の環境変数を設定する必要があります。

現在の役割:

- ジョブキューのポーリング（`npm run worker` = `worker/index.ts`）
- 画像生成ワーカー、リーフ画像・PDFレンダリング（Puppeteer）
- AIキャッチコピー・AI背景生成ジョブの実行

Railway側 Service Variables（必須8種＋任意）:

| 変数名 | 用途 | 必須 |
|---|---|---:|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase接続先。未設定だとワーカーが起動直後に終了します | 必須 |
| `SUPABASE_SERVICE_ROLE_KEY` | ジョブの取得・更新に使用。未設定だとワーカーが起動直後に終了します | 必須 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | ワーカー本体では未使用だが、設定しても害はない | 任意 |
| `GEMINI_API_KEY` | AIキャッチコピー・AI背景生成に使用 | 必須 |
| `IMAGE_GEN_MODEL` | 既定: `gemini-3.1-flash-lite-image` | 必須 |
| `LLM_MODEL` | 既定: `gemini-3.1-flash-lite`。未設定でも既定値が自動で使われるため実害なし | 任意（推奨） |
| `RENDERER_PORT` | レンダラーの待受ポート。既定: `3001` | 必須 |
| `NOTO_FONT_URL` | 日本語フォントURL | 任意 |
| `PUPPETEER_LAUNCH_TIMEOUT_MS` | Puppeteer起動待ち時間。既定: `60000` | 必須 |
| `GOOGLE_SERVICE_ACCOUNT_EMAIL` | Drive転送ジョブ（このワーカー内で処理）に使用 | 必須 |
| `GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY` | Drive転送ジョブに使用 | 必須 |
| `GOOGLE_DRIVE_FINAL_LEAF_FOLDER_ID` | Drive転送先フォルダID | 必須 |

注意:

- `NEXT_PUBLIC_SUPABASE_URL` と `SUPABASE_SERVICE_ROLE_KEY` が未設定の状態でワーカーを起動すると、コンソールに `[worker] SUPABASE URL/KEY が未設定です` と出力され、プロセスが即終了します。
- **Railway上でサービスを削除・再作成すると、設定していた環境変数はすべて失われます。** サービスの作り直しは避け、既存サービスの設定を直接編集してください。
- Railwayには「Environment」（production／staging等）の切り替えがあります。変数を確認する際は、対象のサービスと対象のEnvironmentが正しいか必ず確認してください。
- Railwayの `railway.internal` は外部ブラウザから開けません。外部公開する場合は `Generate Domain` で `up.railway.app` などの公開URLを発行します。
- Vercel・Railwayどちらか一方だけが正しく設定されていても、システム全体は正常に動きません（Vercel=画面/API、Railway=画像/PDF生成、の役割分担のため）。
- **RailwayプロジェクトはTrial/クレジット制です。** ダッシュボード右上に残クレジット・残日数が表示されます。使い切るとワーカーが停止し、リーフ画像生成が全て止まるため、支払い方法の登録と定期的な残高確認が必要です。

## 6. データが保存される場所

### Supabase DB

保存される主なテーブル:

- `quotations`: 見積書単位
- `sheets`: シート単位
- `products`: 商品情報
- `assort_groups`: アソート候補
- `assort_items`: アソート構成商品
- `leaflets`: リーフ情報
- `jobs`: 非同期処理ジョブ
- `alert_flags`: 判定警告
- `app_settings`: 計算設定
- `import_metrics`: 取込精度メトリクス

### Supabase Storage

保存先:

| Bucket | 内容 |
|---|---|
| `quotation-files` | 元見積書、複数資料manifest |
| `product-images` | 抽出した商品画像 |
| `leaflet-images` | 生成済みリーフPNG |
| `leaflet-pdfs` | PDF生成物 |
| `gmail-estimates` | Gmail拡張時のEML、添付 |

### Google Drive

保存されるもの:

- 企画確定したリーフPNG

保存先:

```text
GOOGLE_DRIVE_FINAL_LEAF_FOLDER_ID に設定されたGoogle Driveフォルダ
```

保管方針:

- Google Driveへ転送された確定リーフPNGは、システム側の手動削除や6ヶ月自動削除では削除されません。
- Drive上のアーカイブとして残す前提です。
- 不要になった確定リーフPNGは、Google Drive上で手動削除します。

## 7. 削除と保管期限

手動削除:

- 取込済み見積一覧の「削除」で、DBとStorageの関連データを完全削除します。
- Google Driveへ転送済みの確定リーフPNGは削除されません。

自動削除:

- `quotations.expires_at` を過ぎた見積書を削除します。
- 既定は取り込み日から6ヶ月です。
- Vercel Cronで毎日1回実行します。

確定リーフ:

- 確定リーフ一覧には確定後3日間表示します。
- 3日後に画面から非表示になります。
- DBからは即時削除されず、元の見積書削除時に一緒に削除されます。
- Google Driveへ転送済みの確定リーフPNGは、元の見積書削除後もDrive上に残ります。

## 8. 納品時チェックリスト

- Vercel本番環境に必要な環境変数が入っている
- Railway側のワーカーサービスに必要な環境変数が入っている（「5. Railway」参照）
- `APP_ACCESS_PASSWORD` が設定されている
- パスワードが城東さん経由で共有される
- SupabaseのDB migrationが反映されている
- Storage bucketが作成されている
- Google Driveフォルダが作成されている
- Google Driveフォルダにサービスアカウントが編集者として共有されている
- Gemini APIキーが有効
- AI背景生成モデルが利用可能
- Railwayのワーカーが起動しており、ジョブポーリングログが出力されている
- Railwayの支払い方法が登録されており、残クレジット・残日数に余裕がある
- テスト見積書で取り込み、リーフ編集、Drive転送まで確認済み

## 9. トラブル時の切り分け（Railway編）

画面は開けるがリーフ画像が生成されない、または処理が止まったままの場合:

1. Railwayのプロジェクトを開き、ワーカーサービスのログを確認します。
2. `[worker] ジョブポーリング開始` のログが出ていない場合、サービスが起動していないか、環境変数不足で即終了しています。「5. Railway」の必須環境変数を確認してください。
3. `SUPABASE URL/KEY が未設定です` というログが出ている場合、Railway側のService Variablesが削除・未設定になっています。
4. サービスが正常に起動しているのにジョブが進まない場合は、`GEMINI_API_KEY` の有効性やAPIクレジット残高を確認してください。
5. Railwayプロジェクト内に複数のサービスが存在する場合、意図せず別サービス（ワーカーではないもの）を見ている可能性があります。サービス名を確認してください。
